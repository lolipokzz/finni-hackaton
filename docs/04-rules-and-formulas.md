# 04 — Правила и формулы игровой экономики

Это единственный источник чисел. Все они лежат в `content/config.json` и загружаются в
`EconomyConfig`. В коде числовых литералов экономики быть не должно.

ТЗ отдаёт состав периода, суммы и реакции питомца на усмотрение команды (термины ТЗ, **2.2, 2.5.10**).
Значения ниже — наш выбор для MVP. Менять можно, но одновременно: здесь → код или `config.json` → тесты.
Баланс стратегий ребёнка проверяет `EconomyBalanceTest`: если правка чисел его ломает, она ломает и то, чему учит игра.

## Константы

Числа подобраны и проверены прогоном стратегий ребёнка в [11 — Экономика](11-economy.md); там же ценовая
политика для новых товаров. Сейчас они лежат в `GameRules` и в контенте, позже переедут в `EconomyConfig`.

| Что | Значение | Где в коде |
|---|---|---|
| Стартовые монеты | 50 | `GameRules.START_BALANCE` |
| Карманные за неделю | 50 малыш / 60 подросток / 70 взрослый | `GameRules.weekIncome(stage)` |
| Оплачиваемых заданий за неделю | 2 | `GameRules.TASKS_PER_WEEK` |
| Награда за задание | 5, с ошибкой 3 | `TaskContent` |

| Настроение за неделю | −15 | `GameRules.WEEKLY_MOOD_DECAY` |

## Почему такие числа

Доход недели — опора: каждая цена считается его долей. Целевой план недели 20 / 15 / 15: еда на неделю
стоит 20 (две порции овощей), на необязательное хочется 30–40, а влезает 15. Ребёнок каждую неделю от чего-то
отказывается — это требование **ТЗ 2.1** и критерий **8.4**.

Доход мимо плана (задания и приключение) не больше 30% карманных, иначе план теряет смысл. Первая цель
достигается на 3-й неделе сбалансированного плана, то есть в демо.

## Баланс и накопления

```
balance_after = balance_before + Σ balanceDelta(tx)
savings_after = savings_before + Σ savingsDelta(tx)
```

| Операция | balanceDelta | savingsDelta | Условие |
|---|---|---|---|
| StartCoins | +50 | 0 | один раз |
| WeekIncome | +карманные по стадии | 0 | при закрытии недели |
| TaskReward | +reward или +rewardOnMistake | 0 | лимит заданий |
| AdventureReward | +5 или +3 | 0 | приключение недели, один раз |
| Purchase | −price | 0 | price ≤ balance |
| PlannedDeposit | −plan.savings | +plan.savings | при подтверждении плана |
| Deposit | −a | +a | 0 < a ≤ balance |
| Withdraw | +a | −a | 0 < a ≤ savings, окно с последствиями |
| SavingsBonus | 0 | +5 | при закрытии недели, если отложено ≥ 10 |
| GoalReached | 0 | −goal.cost | savings ≥ goal.cost |

Жёсткие инварианты после любой операции: `balance ≥ 0`, `savings ≥ 0`. Операция, которая их
нарушила бы, отклоняется до изменения состояния.

## План бюджета

```
total = mandatory + optional + savings
Подтвердить можно, если total == balance и нет минусов
```

План раскладывает весь кошелёк. Строка «Копилка» сразу переводится в копилку (`PlannedDeposit`);
забрать можно в любой момент. Подсказка у строки «Обязательное» — цена еды на неделю
(`cheapestFoodFor(35)` = 20), а не самой дешёвой порции.

## Факт недели

```
mandatorySpent = Σ price покупок MANDATORY за неделю
optionalSpent  = Σ price покупок OPTIONAL за неделю
saved          = Σ пополнений − Σ снятий за неделю   (может быть < 0; покупка цели сюда не входит)
weekSatiety    = Σ satiety покупок за неделю
```

## Дела недели и итоги

Вместо звёзд — четыре дела. Каждое сделанное дело — шаг роста. Дела считаются в любой момент недели
(`GameSnapshot.weekDeeds`), поэтому видны по ходу недели; в итог идёт то, что сделано к её закрытию.

| Дело | Условие |
|---|---|
| Финни сыт | `weekSatiety ≥ 35` |
| Финни не скучает | `mood ≥ 40` при закрытии недели |
| Копилка по плану | `saved > 0 && saved ≥ plan.savings` |
| Траты по плану | `optionalSpent ≤ plan.optional` |

```
steps = число сделанных дел   // 0..4
```

Перерасход на обязательное дела не отнимает: ребёнок не должен бояться накормить питомца.
Задания и приключения шагов не дают.

## Состояние питомца

Сытость ∈ [0, 100], настроение ∈ [20, 100], всегда `clamp`.

**После покупки:** `satiety += item.satiety`, `mood += item.mood`.

**При закрытии недели:**

```
satiety = clamp(satiety − 35)
lasting = min(3 × (вещи в гардеробе + достигнутые цели), 9)
mood    = clamp(mood − 15 + lasting)        // от дел не зависит
```

**При достижении цели:** `mood = clamp(mood + 10)`, дальше цель радует как вещь.

**Подписи (вычисляются, не хранятся):**

```
moodLabel = mood ≥ 70 → «радостный» | mood ≥ 40 → «спокойный» | иначе «скучает»
satiety < 30 → «голоден»
```

Самое низкое состояние — «скучает», а не «грустный» (этика, ТЗ 8.1).

## Рост питомца

```
growthPoints += steps            // при каждом закрытии недели, только вверх
stage = последняя стадия, у которой minGrowthPoints ≤ growthPoints
```

| Стадия | Шагов | При всех 4 делах | При 3 делах |
|---|---|---|---|
| Малыш | 0–7 | старт | старт |
| Подросток | 8–15 | 2-я неделя | 3-я неделя |
| Взрослый | 16+ | 4-я неделя | 6-я неделя |

Новая стадия поднимает карманные (50 → 60 → 70) уже со следующей недели. Стадия не откатывается никогда.

## Срок достижения цели

```
remaining = goal.cost − savings
avgDeposit = среднее(saved по последним ≤ 3 закрытым периодам, где saved > 0)
             если закрытых периодов нет → plan.savings текущего периода
etaPeriods = avgDeposit > 0 ? ceil(remaining / avgDeposit) : null
```

Показываем «≈ N недель». `null` → «Начни откладывать, и я посчитаю срок». Формула умышленно
простая, ребёнку её можно объяснить одной фразой: «осталось поделить на то, сколько ты обычно
откладываешь» (**ТЗ 2.5.7**).

При снятии до подтверждения считаем `etaAfter` с `savings − amount` и показываем «было → станет».

## Задания

```
rewardPaid = success ? task.reward : task.rewardOnMistake
```

Оценка по типам (детали формата в [05](05-content-model.md#задания--tasksjson)):

- `CHOICE`: `success = options[chosen].correct`.
- `ALLOCATE`: `success = Σ buckets == total && mandatory ≥ rule.mandatoryMin && savings ≥ rule.savingsMin`.
- `SHOP_LIST`: `success = все обязательные товары выбраны && Σ price ≤ budget`.

Лимит: `tasksDoneThisPeriod < tasksPerPeriod`, кроме демо-режима.

Повтор: неуспешное задание доступно снова, если `currentPeriod.index > lastResult.periodIndex`.

## Раздел взрослого: барьер

```
a, b ∈ [10, 89], a + b ≤ 99 → «a + b = ?»
```

3 попытки, потом новый пример. Никаких паролей: их пришлось бы хранить, а хранить нечего.

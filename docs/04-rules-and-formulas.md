# 04 — Правила и формулы игровой экономики

Это единственный источник чисел. Все они лежат в `content/config.json` и загружаются в
`EconomyConfig`. В коде числовых литералов экономики быть не должно.

ТЗ отдаёт состав периода, суммы и реакции питомца на усмотрение команды (термины ТЗ, **2.2, 2.5.10**).
Значения ниже — наш выбор для MVP. Менять можно, но одновременно: здесь → `config.json` → тесты.

## Константы

```json
{
  "currencyName": "монеты",
  "startBalance": 100,
  "periodIncome": 60,
  "dailyBonus": { "enabled": false, "amount": 5 },
  "tasksPerPeriod": 2,
  "planStep": 5,
  "mandatoryNeeds": ["food", "care"],
  "pet": {
    "initialState": { "satiety": 70, "care": 70, "mood": 70 },
    "decayPerPeriod": { "satiety": 35, "care": 25, "mood": 10 },
    "moodDeltaByScore": { "0": -15, "1": 0, "2": 10, "3": 20 },
    "moodLabels": { "happy": 70, "calm": 40 },
    "flags": { "hungryBelow": 30, "unkemptBelow": 30 },
    "stages": [
      { "id": "BABY",  "minGrowthPoints": 0 },
      { "id": "TEEN",  "minGrowthPoints": 5 },
      { "id": "ADULT", "minGrowthPoints": 10 }
    ],
    "goalReachedMoodBonus": 30
  },
  "goalEta": { "historyPeriods": 3 },
  "adultBonus": { "min": 5, "max": 50 }
}
```

## Почему такие числа

Доход за период (60) специально меньше, чем «еда + уход + одна игрушка + пополнение копилки»
(15 + 10 + 20 + 20 = 65). Ребёнок каждый период должен от чего-то отказаться или заработать заданием.
Это требование **ТЗ 2.1** «за один период нельзя купить всё сразу» и критерий **8.4** «механика требует выбора».

Стартовый баланс 100 больше дохода, чтобы в первом периоде было легко и приятно, а дефицит
появился со второго.

## Баланс и накопления

```
balance_after = balance_before + Σ balanceDelta(tx)
savings_after = savings_before + Σ savingsDelta(tx)
```

| Операция | balanceDelta | savingsDelta | Условие |
|---|---|---|---|
| START_BALANCE | +100 | 0 | один раз |
| PERIOD_INCOME | +60 | 0 | при создании периода n ≥ 2 |
| TASK_REWARD | +reward или +rewardOnMistake | 0 | лимит заданий |
| DAILY_BONUS | +5 | 0 | новая дата, не демо |
| ADULT_BONUS | +a | 0 | 5 ≤ a ≤ 50 |
| PURCHASE | −price | 0 | price ≤ balance |
| SAVINGS_DEPOSIT | −a | +a | 0 < a ≤ balance |
| SAVINGS_WITHDRAW | +a | −a | 0 < a ≤ savings, подтверждение |
| GOAL_REACHED | 0 | −goal.cost | savings ≥ goal.cost |

Жёсткие инварианты после любой операции: `balance ≥ 0`, `savings ≥ 0`. Операция, которая их
нарушила бы, отклоняется с `GameError` до изменения состояния.

Нехватка при покупке: `missing = price − balance`.

## План бюджета

```
total = mandatory + optional + savings
remainder = budgetAtPlanning − total
Подтвердить можно, если total ≤ budgetAtPlanning и total > 0
```

Все три значения кратны `planStep = 5` (для удобства детской арифметики). Ноль в любой категории разрешён.

## Факт периода

```
mandatorySpent = Σ price по покупкам с category = MANDATORY за период
optionalSpent  = Σ price по покупкам с category = OPTIONAL за период
saved          = Σ депозитов − Σ снятий за период   (может быть < 0)
extraIncome    = Σ TASK_REWARD + DAILY_BONUS + ADULT_BONUS за период
```

Сравнение план/факт на экране показывается по каждой категории как «план N / факт M»
и прогресс-бар `min(M / N, 1)`. Если N = 0, бар не рисуем, пишем «не планировал».

## Итоги периода

Три критерия, каждый 0 или 1:

| Критерий | Формула | Фраза ребёнку при ✓ | Фраза при ○ |
|---|---|---|---|
| A. Обязательное закрыто | `mandatoryNeeds ⊆ coveredNeeds` | «Ты купил всё нужное — Финни сыт и ухожен» | «Финни не хватило {список}. Купи это первым на новой неделе» |
| B. План по желаемому соблюдён | `optionalSpent ≤ plan.optional` | «Ты уложился в план на желаемое» | «На желаемое ушло больше плана. В следующий раз сверься с планом» |
| C. Отложил | `saved > 0 && saved ≥ plan.savings` | «Ты отложил {saved} — до цели ближе» | «В этот раз копилка не пополнилась. Попробуй отложить хотя бы 5» |

```
score = A + B + C          // 0..3
```

Почему не штрафуем за перерасход по обязательному: еда для питомца важнее плана, и ребёнок
не должен бояться купить нужное.

## Состояние питомца

Значения `satiety`, `care`, `mood` ∈ [0, 100], всегда `clamp`.

**После покупки:** `state += item.effects` (например корм: satiety +40, mood +5).

**При закрытии периода:**

```
satiety = clamp(satiety − 35)
care    = clamp(care − 25)
mood    = clamp(mood − 10 + moodDeltaByScore[score])
```

**При достижении цели:** `mood = clamp(mood + 30)`.

**Подписи (вычисляются, не хранятся):**

```
moodLabel = mood ≥ 70 → «Радостный» | mood ≥ 40 → «Спокойный» | иначе «Грустный»
flags: satiety < 30 → «Голодный», care < 30 → «Хочет ухода»
```

На главном экране: картинка питомца с выражением по `moodLabel`, три шкалы с иконкой, подписью и числом.
Флаги показываются как подсказка «Финни голоден — купи еду» с переходом в магазин.

Объяснение причины настроения (**ТЗ 2.5.10**): под питомцем всегда одна фраза, выбранная по приоритету:
1. `HUNGRY` → «Голоден: на этой неделе не было еды»
2. `UNKEMPT` → «Хочет ухода: не было ухода»
3. последний `PeriodSummary.explanation[0]`
4. последняя покупка/пополнение → «Рад новому мячику» / «Гордится, что ты копишь»
5. по умолчанию → «Ждёт твоих решений»

## Рост питомца

```
growthPoints += score            // при каждом закрытии периода, только вверх
stage = последняя стадия, у которой minGrowthPoints ≤ growthPoints
```

| Стадия | Очки | Как быстро достижимо |
|---|---|---|
| Малыш | 0–4 | старт |
| Подросток | 5–9 | 2 идеальных периода или 3 хороших |
| Взрослый | 10+ | 4 идеальных периода или 5 хороших |

За 5 демонстрационных периодов эксперт увидит минимум одну смену стадии при разумной игре
(шаг 10 сценария). Стадия не откатывается никогда, даже при score 0.

## Срок достижения цели

```
remaining = goal.cost − savings
avgDeposit = среднее(saved по последним ≤ 3 закрытым периодам, где saved > 0)
             если закрытых периодов нет → plan.savings текущего периода
etaPeriods = avgDeposit > 0 ? ceil(remaining / avgDeposit) : null
```

Показываем «≈ N недель». `null` → «Начни откладывать, и я посчитаю срок». Формула умышленно
простая, ребёнку её можно объяснить одной фразой: «осталось поделить на то, сколько ты обычно
откладываешь» (**ТЗ 2.5.7**).

При снятии до подтверждения считаем `etaAfter` с `savings − amount` и показываем «было → станет».

## Задания

```
rewardPaid = success ? task.reward : task.rewardOnMistake
```

Оценка по типам (детали формата в [05](05-content-model.md#задания--tasksjson)):

- `CHOICE`: `success = options[chosen].correct`.
- `ALLOCATE`: `success = Σ buckets == total && mandatory ≥ rule.mandatoryMin && savings ≥ rule.savingsMin`.
- `SHOP_LIST`: `success = все обязательные товары выбраны && Σ price ≤ budget`.

Лимит: `tasksDoneThisPeriod < tasksPerPeriod`, кроме демо-режима.

Повтор: неуспешное задание доступно снова, если `currentPeriod.index > lastResult.periodIndex`.

## Раздел взрослого: барьер

```
a, b ∈ [10, 89], a + b ≤ 99 → «a + b = ?»
```

3 попытки, потом новый пример. Никаких паролей: их пришлось бы хранить, а хранить нечего.

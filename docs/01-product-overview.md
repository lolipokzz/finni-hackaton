# 01 — Продукт, границы, глоссарий

## Что делаем

Мобильное приложение для Android «Питомец Финни»: ребёнок 7–11 лет заводит виртуального питомца,
получает игровую валюту, планирует её на три направления (обязательное, желаемое, накопления),
покупает вещи для питомца, выполняет учебные задания и копит на цель. Состояние и рост питомца
зависят от качества финансовых решений за несколько игровых периодов.

Это бесплатный просветительский прототип без реальных денег, без сети, без аккаунтов.
Все данные живут только на устройстве (**ТЗ 2, 2.1, 3.5**).

## Образовательные результаты, на которые работаем (ТЗ 1)

| № | Компетенция | Какая механика её формирует |
|---|---|---|
| 1 | Понимать назначение бюджета; расходы не больше доходов | План бюджета ограничен доступной суммой, отрицательный баланс невозможен |
| 2 | Различать обязательные и необязательные расходы | Два типа товаров в магазине, две категории плана, чек-лист «обязательное на период» |
| 3 | Планировать покупки при ограниченном бюджете | Дохода на период не хватает на всё; задания-сценарии типа «список покупок» |
| 4 | Ставить краткосрочную цель и регулярно откладывать | Цели с ценой, пополнение копилки, срок достижения по среднему пополнению |
| 5 | Оценивать свои решения и объяснять последствия | Обратная связь после каждого действия, итоги периода «план vs факт» |
| 6 | Пользоваться приложением с участием взрослого | Раздел для взрослого: цели, пройденные темы, прогресс, сброс |

## Три типа решений

Вся игра построена на одном выборе, который ребёнок делает снова и снова:

1. **Потратить на обязательное** — еда, уход. Без этого питомцу плохо.
2. **Потратить на желаемое** — игрушки, украшения. Радуют, но можно отложить.
3. **Отложить** — в копилку на цель.

Эти три слова должны быть одинаковыми во всём приложении: в онбординге, в плане бюджета, в магазине,
в итогах периода. В коде это `SpendCategory.MANDATORY`, `SpendCategory.OPTIONAL`, `SpendCategory.SAVINGS`.

## Принципы (ТЗ 2.2), которые проверяют эксперты

| Принцип | Что это значит для кода |
|---|---|
| Обучение действием | Сначала действие, потом экран «что изменилось и почему». Никаких длинных правил до игры |
| Объяснимость | Баланс, копилка, настроение и стадия никогда не меняются молча. Каждое изменение сопровождается записью с источником и суммой |
| Безопасная ошибка | Ошибка не обнуляет прогресс. Стадия развития не откатывается. После ошибки всегда есть путь восстановления: задание, новый план, отказ от желаемого |
| Возрастная уместность | Числа до 200, только сложение и вычитание, фразы до 10 слов, кнопки от 48 dp, текст от 16 sp |
| Финансовая нейтральность | Нет брендов, банков, реальных продуктов, персональных советов |

## Роли (ТЗ 2.3)

- **Ребёнок** — основной пользователь, принимает все финансовые решения. Родитель не решает за него.
- **Взрослый** — заходит в защищённый раздел (арифметический барьер), видит цели и прогресс без негативных оценок,
  может сбросить или удалить профиль, включить демо-режим, отключить звуки.

## Что запрещено (ТЗ 2.7, 3.5) — чек-лист перед каждым релизом

- [ ] Нет реальных платежей, подписок, внутриигровых покупок за деньги, рекламы, лутбоксов.
- [ ] Нет регистрации, сбора имени, телефона, e-mail, фото. Поле имени подписано «игровое имя».
- [ ] Нет внешних ссылок, доступных ребёнку без раздела взрослого.
- [ ] Нет разрешений Android, кроме необходимых (для MVP — ни одного runtime-разрешения).
- [ ] Нет секретов в репозитории (keystore, пароли).
- [ ] Питомец не умирает, не болеет и не травмируется от ошибок ребёнка. Единственное исключение — заранее
      спроектированное событие «непредвиденные расходы» (см. [05](05-content-model.md#события-периода--eventsjson-опционально-после-mvp)).
- [ ] Тексты не стыдят и не пугают. Запрещены формулировки вида «ты плохо заботишься», «питомцу плохо из-за тебя».
- [ ] Сброс и удаление данных доступны взрослому в приложении, с подтверждением.

## Сквозной сценарий (ТЗ Приложение А) — это наш happy path

Шаги отмеченные «Демо» показываются экспертам вживую на финальной сборке. Каждый шаг должен
проходиться без ожидания реального времени.

| № | Действие | Демо | Экран (см. [07](07-screens.md)) |
|---|---|---|---|
| 1 | Первый запуск, знакомство с целью игры и тремя типами решений | Да | Onboarding |
| 2 | Создание локального профиля без реальных данных | Да | CreateProfile |
| 3 | Внешний вид питомца и игровое имя | Да | CreatePet |
| 4 | Стартовый бюджет, текущая цель, доступные задания | Да | Home |
| 5 | Распределение на обязательное, желаемое, накопления | Да | BudgetPlan |
| 6 | Выполнение задания, получение валюты с объяснением | Да | Tasks → TaskResult |
| 7 | Обязательная и необязательная покупка, попытка купить при нехватке | Да | Shop → PurchaseConfirm |
| 8 | Выбор цели и пополнение накоплений | Да | Savings |
| 9 | Обратная связь о балансе, плане, состоянии питомца | — | Home, PeriodSummary |
| 10 | Переход к следующему периоду, изменение прогресса или стадии | Да | PeriodSummary |
| 11 | Закрытие и повторный запуск с сохранением прогресса | Да | Home |
| 12 | Раздел взрослого, сброс тестового профиля | Да | AdultGate → Adult |

## Глоссарий

Термин ТЗ → как называем в коде. Одно понятие — одно имя.

| Термин ТЗ | В коде | Пояснение |
|---|---|---|
| Игровая валюта | `Money` (typealias Int), UI-название «монеты» | Целые числа, без копеек. Название валюты берётся из `config.json` |
| Доступный баланс | `Wallet.balance` | Можно тратить прямо сейчас |
| Накопления | `Wallet.savings` | Отложено, в балансе не учитывается |
| Финансовая цель | `Goal`, `GoalProgress` | Предмет с ценой, на который копим |
| Игровой период | `Period` | Цикл: план → действия → итоги. У нас называется «неделя» в UI, но к реальному времени не привязан |
| План личного бюджета | `BudgetPlan` | Три суммы: обязательное, желаемое, накопления. Фиксируется подтверждением |
| Фактическое исполнение | `PeriodFacts` | Сколько реально потрачено и отложено за период |
| Обязательные расходы | `SpendCategory.MANDATORY` | Товары с `category = MANDATORY` |
| Необязательные расходы | `SpendCategory.OPTIONAL` | Товары с `category = OPTIONAL` |
| Состояние питомца | `PetState` (сытость, уход, настроение) | Обратимо, меняется от каждого действия |
| Стадия развития | `PetStage` | Меняется только по итогам периодов, не откатывается |
| Задание | `Task`, `TaskResult` | Игровая ситуация с выбором и последствием |
| Локальный игровой профиль | `Profile` + всё состояние `GameState` | Один профиль на устройство в MVP |
| Тестовый профиль | `GameState` с `demoMode = true` | Создаётся кнопкой в разделе взрослого, сбрасывается к исходному |
| Демонстрационный режим | `Settings.demoMode` | Снимает все привязки к календарю |
| Раздел для взрослого | `AdultSection` | Защищён арифметическим примером |

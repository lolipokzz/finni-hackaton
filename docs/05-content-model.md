# 05 — Модель учебного контента

Требование **ТЗ 2.5.14 и 3.2**: учебный контент отделён от интерфейсного кода, новое задание добавляется
без переработки логики. Критерий **8.2**: «разделение учебного контента от логики интерфейса».

## Где лежит

Контент — это неизменяемые справочники: уровни с упражнениями, приключения, товары, цели и фразы обратной связи.
Они лежат отдельно от экранов и от правил игры:

| Что | Где | Формат |
|---|---|---|
| Карта заданий: 15 уровней, 90 упражнений | `app/src/main/java/.../data/content/TaskContent.kt` | `defaultLevels`: список `Level`, в каждом 6 объектов `Task` |
| Приключения недели (5 шт.) | `data/content/AdventureContent.kt` | список `Adventure` |
| Товары магазина (11 шт.) | `data/content/ShopContent.kt` | список `ShopItem` |
| Цели копилки (4 шт.) | `data/content/GoalContent.kt` | список `SavingsGoal` |
| Фразы обратной связи (83 ключа) | `app/src/main/assets/content/feedback.json` | JSON «ключ → шаблон» |
| 3D-модели и раскраски кота | `app/src/main/assets/cat/` | GLB и WebP |

Задания, приключения, товары и цели сейчас описаны Kotlin-списками, а не JSON-файлами: для прототипа
это проще проверить компилятором и тестами. Всё равно это данные, а не логика: списки не содержат
условий и вычислений, их читают правила из `domain/` (`GameEngine`, `Task.evaluate`, `AdventureRules`)
и экраны из `presentation/`. Перенос в JSON — см. «Дальнейшее развитие» ниже.

### Как загружается

- `defaultContent()` (`data/content/DefaultContent.kt`) собирает все списки в один объект
  `Content` (`domain/content/Content.kt`). Koin отдаёт его как синглтон (`app/di/AppModule.kt`),
  ViewModel и репозиторий получают его через конструктор.
- `feedback.json` читается один раз при старте (`app/di/AssetsModule.kt`) функцией `parseFeedback`
  (`data/content/FeedbackContent.kt`) в объект `Feedback`. Лишний или пропущенный ключ — ошибка контента,
  а не пустая строка на экране.

## Питомец

Питомец в игре один — кот: у него весь функционал (анимации эмоций, гардероб, поглаживание, голос).
Ребёнок выбирает раскраску и имя.

- Модели по стадиям роста: `assets/cat/{baby,teen,adult}.glb` — один скелет и набор анимаций.
- Раскраски: `PetColor` (`domain/pet/model/PetLook.kt`) — обычная рыжая (текстура из модели) и 8
  перекрашенных текстур шерсти в `assets/cat/skins/<цвет>.webp`. Итого 9 различимых вариантов (**ТЗ 2.6**).
- Вещи гардероба — узлы модели (`Acc_Cap`, `Acc_Glasses`, `Acc_BowTie`), одинаковые на всех стадиях.
  Какой товар какой узел включает — `presentation/pet/PetAssets.kt`.

## Задания — `TaskContent.kt`

Карта содержит **15 уровней на 5 игровых недель**, по одному уровню каждой темы на неделю.
В каждом уровне **6 упражнений**, всего **90**: по 30 на планирование бюджета, сбережения, платежи и покупки.
`defaultContent()` передаёт `defaultLevels` в `Content.levels`. Тема, название, неделя открытия и награда относятся
к уровню; отдельное упражнение содержит ситуацию, механику, подсказку и объяснения.

```kotlin
data class Level(
    val id: String,
    val topic: TaskTopic,              // BUDGET | SAVINGS | PAYMENTS
    val title: String,
    val week: Int,                     // игровая неделя открытия
    val reward: Int,                   // 3 монеты за уровень без ошибок
    val rewardOnMistake: Int,          // 2 монеты за уровень с ошибками
    val tasks: List<Task>,             // сейчас по 6 упражнений
)

data class Task(
    val id: String,
    val intro: String,                 // ситуация
    val explanationSuccess: String,    // объяснение после верного решения
    val explanationMistake: String,    // объяснение после ошибки и как исправить
    val hint: String,
    val payload: TaskPayload,          // механика, см. ниже
)
```

### Прохождение, награды и открытие

- `LevelPlayViewModel` случайно выбирает **4 из 6** упражнений и показывает выбранные в исходном порядке
  (`GameRules.TASKS_PER_LEVEL = 4`). Набор выбирается заново при новом прохождении, в том числе в демо.
  Конкретное упражнение не гарантировано в каждом наборе; демонстрационный сценарий должен учитывать это.
- После каждого ответа показываются `explanationSuccess` или `explanationMistake`; у `Choice` дополнительно
  показывается последствие выбранного варианта. Ошибка не прерывает уровень и не списывает монеты.
- После четырёх ответов `GameEngine.completeLevel` сохраняет первый результат: **3 монеты без ошибок,
  2 монеты при любой ошибке**. Звёзды: 3 без ошибок, 2 с одной, 1 с двумя и более. Награда начисляется
  **один раз за уровень**, с записью в журнале; за отдельный ответ монет нет. Это правило действует и в демо.
- В обычной игре уровень доступен, когда наступила его игровая неделя и пройден предыдущий уровень
  в `defaultLevels` (`GameState.levelStatus`). Пройденным считается и уровень с ошибками; пропущенные уровни
  остаются доступными позже. Приключение недели открывается после всех уровней до текущей недели включительно.
- В демо все **непройденные** уровни и приключения доступны сразу, независимо от недели и порядка.
  Пройденный уровень сохраняет статус `DONE`; повторить первое прохождение с наградой можно после сброса демо.
- Для пройденного уровня доступно **золотое испытание**: новый набор из 4 упражнений, без подсказок,
  120 секунд активного ответа на весь набор (30 × 4). Таймер останавливается на объяснениях и в фоне.
  Все ответы верны и время не превышено — id попадает в `goldLevels`. **Монет за испытание нет**,
  первый результат уровня не заменяется. Неудача не уменьшает уже полученный прогресс.

Сложность растёт по неделям: от сравнения небольших сумм к вычислению срока и покупкам в несколько действий.
В актуальном контенте есть сложение и вычитание, а также повторное сложение, умножение и деление при расчёте
регулярных накоплений. Объяснения опираются на конкретные суммы и промежуточные шаги. При добавлении текста
следует сохранять короткие условия, понятные числа и объяснение ошибки; возрастную понятность нужно проверять
на пользователях, а не выводить только из ограничения длины фразы.

Механики (`domain/task/model/TaskPayload.kt`), оценка ответа — `Task.evaluate` (`domain/task/TaskEvaluation.kt`):

| Механика | Что делает ребёнок | Верно, если |
|---|---|---|
| `Choice` — ситуация с вариантами | Выбирает действие; у каждого варианта своё последствие (`consequence`) | выбран вариант с `correct = true` |
| `Allocate` — раздели сумму | Раскладывает `total` монет шагом `step` по кучкам «Обязательное», «Необязательное», «Копилка» | сумма равна `total`, обязательное ≥ `mandatoryMin`, копилка ≥ `savingsMin` |
| `ShopList` — собери покупки | Выбирает товары в пределах `budget`, экран показывает сумму и остаток | все обязательные выбраны и сумма ≤ `budget` |

### Образовательная карта уровней (ТЗ 5.7)

Темы и ожидаемые навыки ниже связаны с шестью образовательными результатами из

Для каждого уровня приведён пример сценария, его правильная логика и объяснение ребёнку из контента.
Следующий раздел перечисляет все 90 упражнений: тема и навык наследуются от уровня, условия и объяснения

Учебные суммы принадлежат условиям упражнений и могут отличаться от цен действующего магазина и целей.

| Неделя / уровень | Тема и ожидаемый навык | Сценарий | Правильная логика | Объяснение ребёнку: пример |
|---|---|---|---|---|
| 1 · `w1_budget` — Обязательное или нет | Бюджет: отличать необходимое от желаемого, распределять первую сумму | 20 монет, еда 10, часть отложить | На обязательное ≥10, в копилку ≥5, сумма трёх частей 20 | «Еда оплачена, и немного отложено. Это и есть план!» |
| 1 · `w1_savings` — Зачем копилка | Сбережения: понимать цель и регулярное пополнение | Мяч 20, откладываем по 5 | Четыре пополнения по 5 дают 20 | «5 + 5 + 5 + 5 = 20. Четыре недели — и мяч в лапах.» |
| 1 · `w1_payments` — Хватит ли монет? | Покупки: сравнивать цену с балансом, считать остаток и сдачу | 15 монет, корм стоит 10 | Покупка доступна, остаток 15 − 10 = 5 | «Хватит, и ещё 5 останется: 15 − 10 = 5.» |
| 2 · `w2_budget` — План на неделю | Бюджет: составлять план до покупок и сохранять деньги на обязательное | 50 монет, еда 20, отложить хотя бы 10 | На обязательное ≥20, в копилку ≥10, сумма 50 | «Обязательное закрыто, копилка пополнена!» |
| 2 · `w2_savings` — Взять из копилки? | Сбережения: считать недостающую сумму и последствия снятия | 40 в копилке на велосипед, хочется чипсы за 15 | Отложить необязательную покупку, сохранить накопления | «Копилка — для цели. Чипсы можно купить с монет на неделю или подождать.» |

| 3 · `w3_budget` — Сначала обязательное | Бюджет: сверять план с расходами и исправлять перерасход | На необязательное было 20, потрачено 25 | На следующей неделе уменьшить необязательные траты | «Перерасход не беда, если его заметить. На следующей неделе тратим на необязательное чуть меньше.» |
| 3 · `w3_savings` — Когда накопим? | Сбережения: рассчитывать срок с учётом уже накопленного и регулярного взноса | Цель 80, накоплено 20, взнос 20 | Осталось 60; ещё три недели по 20 | «Не хватает 60, а 60 — это 3 недели по 20.» |
| 3 · `w3_payments` — Выгодная покупка | Покупки: сравнивать общую стоимость предложений | Корм 15 и наклейки 5 или корм с подарком за 25 | Отдельно 20, на 5 дешевле набора | «15 + 5 = 20, а это меньше 25. „Подарок“ не бесплатный: сравнивай, сколько стоит всё вместе.» |
| 4 · `w4_budget` — Неожиданная трата | Бюджет: сохранять приоритет обязательного при незапланированном расходе | Нужны овощи за 10, деньги на обязательное потрачены | Перенести 10 из необязательного, отложив радости | «Из необязательного: радости подождут, а еда — нет.» |
| 4 · `w4_savings` — Цель побольше | Сбережения: учитывать бонус, остаток до цели и снятия | Цель 100, накоплено 60, снимаем 20 | В копилке 40, до цели 60 | «60 − 20 = 40 в копилке. 100 − 40 = 60 не хватает.» |
| 4 · `w4_payments` — Сравни и посчитай | Покупки: сравнивать несколько цен и проверять сумму корзины | Одинаковый мяч по 30, 25 и 28 | Минимум 25; относительно 30 экономия 5 | «Самый дорогой — 30, самый дешёвый — 25. 30 − 25 = 5.» |
| 5 · `w5_budget` — Большой план | Бюджет: планировать на несколько недель и копить на желаемое без ущерба обязательному | Кепка 40, на необязательное по 10 в неделю | Откладывать четыре недели по 10 | «Большую покупку собирают по частям: по 10 в неделю — за 4 недели.» |
| 5 · `w5_savings` — Мастер копилки | Сбережения: считать срок с учётом снятий, бонусов и нескольких целей | Цель 90, взнос 20, каждую неделю снимаем 5 | Чистое пополнение 15; шесть недель до 90 | «Прибавляется 15 в неделю, а 90 — это 6 раз по 15.» |
| 5 · `w5_payments` — Умный покупатель | Покупки: сравнивать равные количества и распознавать рекламную спешку | Три банки по 12 или равная им большая за 30 | Маленькие стоят 36, большая дешевле на 6 | «Три по 12 — это 36, а большая — 30. Большая выгоднее на 6.» |

#### w1_budget — Обязательное или нет

Неделя 1; тема — планирование бюджета. [Исходный контент](../app/src/main/java/ru/larpinovplay/finniapp/data/content/TaskContent.kt#L13).

### Как добавить упражнение или уровень

1. Для нового упражнения добавить `choice(...)`, `allocate(...)` или `shopList(...)` в нужный `level(...)`
   списка `defaultLevels` в `TaskContent.kt`. Задать уникальный во всём контенте id, условие, подсказку,
   объяснения верного и ошибочного ответа. В выборе ровно один `right(...)`; в раскладке сумма минимумов
   не превышает `total`, в корзине обязательные покупки укладываются в бюджет.
2. Для нового уровня добавить `level(id, topic, title, week, ...)` в `defaultLevels` на нужное место:
   порядок списка задаёт предыдущий уровень на тропинке. Тема — `BUDGET`, `SAVINGS` или `PAYMENTS`;
   упражнений должно быть больше `GameRules.TASKS_PER_LEVEL` (сейчас 4), чтобы наборы могли различаться.
   Helper `level` задаёт награды 3/2; не начислять отдельные награды упражнениям.
3. Обновить эту карту: тему, навык, условия, правильную логику и объяснения, а также счётчики и описание
   демонстрации. При добавлении шестой недели обновить проверку диапазона недель в `ContentMinimumsTest`
   и оценить длительность сценария и экономику.
4. Запустить `./gradlew :app:testDebugUnitTest`. `ContentMinimumsTest` проверяет идентификаторы,
   темы, решаемость и объяснения; `EconomyBalanceTest` — долю наград. Вручную проверить новый материал
   с верным и ошибочным ответом в демо. Это инструкция проверки при изменении контента, не отчёт о её проведении.

Для упражнений на существующих механиках основные правила, UI и формат сохранения не меняются;
добавление Kotlin-контента требует пересборки APK. Существующие id уровней сохранять: на них ссылается
прогресс. Новая механика — отдельная функция: новый вариант `TaskPayload`, ветка `Task.evaluate`,
виджет в `TaskWidgets.kt` и соответствующие проверки.

## Приключения недели — `AdventureContent.kt`

| friend_gift | Подарок другу | накопление на большую покупку |

Новое приключение добавляется так же, как задание: объект `Adventure` в `defaultAdventures`, затем
`AdventureContentTest`. Новый вид шага — новый класс в `AdventureScene` и виджет на экране приключения.

## Тексты обратной связи — `assets/content/feedback.json`

Плоский JSON «ключ → шаблон» с плейсхолдерами вида `{n}`, `{item}`, `{goal}`, `{price}`, `{plan}`, `{spent}`.
Ключи фиксированы в `FeedbackKey` (`domain/content/FeedbackKey.kt`): домен называет, что произошло,
а слова берутся из файла.

| Группа ключей | О чём |
|---|---|
| `ledger.*` | Причины движений в журнале монет: доход недели, задание, копилка, цель |
| `period.*`, `stage.up` | Итоги недели: что вышло с каждым делом, рост питомца |
| `deed.*` | Дела недели: что сделать |
| `finish.*` | Почему неделю пока нельзя закончить |
| `plan.*` | Подсказки в окне плана недели |
| `deposit.*`, `withdraw.*` | Копилка: отказ, снятие |
| `adventure.*` | Подсказки и объяснения в приключениях |
| `say.*` | Реплики Финни |
| `storage.*` | Ошибки сохранения, понятные ребёнку |
| `topic.*` | Названия тем заданий |

Пример:

```json
{
  "ledger.week_income": "Карманные деньги",
  "period.c_ok": "Ты отложил {n} — до цели ближе",
  "finish.no_adventure": "На этой неделе тебя ждёт приключение. Оно в разделе «Задания»"
}
```

Правила текстов: без «ты виноват», «плохо», «неправильно». Ошибка описывается через питомца и
следующий шаг, не через оценку ребёнка (**ТЗ 3.5, 8.1**).

## Справочник терминов

Словарик (**ТЗ 2.5.11**) — список «термин → объяснение» на экране настроек
(`presentation/screens/settings/SettingsScreen.kt`, `glossary`): монеты, обязательное, необязательное,
копилка, цель, план недели, неделя, сытость, настроение.

## Демо-профиль

Отдельного файла нет: демо-профиль строит `GameRepositoryImpl.resetToDemo()` — новая игра со
стартовым балансом `GameRules.START_BALANCE`, флагом `demoMode` и котом «Финни Демо» коралловой раскраски.
Все уровни и приключения можно открыть сразу, игровую неделю — завершить без ожидания календарного дня.
Повторный сброс демо очищает результаты уровней, золотые испытания и остальной тестовый прогресс.
До включения демо обычная игра сохраняется отдельно; `exitDemo()` возвращает её. Подробный порядок
проверки — [09 — Тест-кейсы](09-test-cases.md#e2e-обязательный-сценарий).

## Дальнейшее развитие

Перенести уровни с упражнениями, приключения, товары и цели в JSON-файлы `assets/content/` рядом с
`feedback.json`, чтобы редактировать данные без изменения Kotlin-исходников. Замена упакованных в APK
assets по-прежнему потребует новой сборки приложения; загрузчика внешних обновлений сейчас нет.

1. Описать DTO с `@Serializable` по образцу `data/settings/SettingsSaveFile.kt` и мапперы в доменные модели.
2. Читать файлы в `AssetsModule` так же, как `feedback.json`, и собирать из них `Content` вместо `defaultContent()`.
3. Оставить тесты контента: они будут читать JSON из `src/main/assets`, как `FeedbackContentTest`.
4. Вынести обучающие карточки знакомства и словарик из `SettingsScreen.kt` в справочник текстов.

Доменные модели, правила и экраны при этом не меняются: они уже получают `Content` через конструктор.

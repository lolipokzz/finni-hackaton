# 05 — Модель учебного контента

Требование **ТЗ 2.5.14 и 3.2**: учебный контент отделён от интерфейсного кода, новое задание добавляется
без переработки логики. Критерий **8.2**: «разделение учебного контента от логики интерфейса».

## Где лежит

Контент — это неизменяемые справочники: задания, приключения, товары, цели и фразы обратной связи.
Они лежат отдельно от экранов и от правил игры:

| Что | Где | Формат |
|---|---|---|
| Задания (6 шт.) | `app/src/main/java/.../data/content/TaskContent.kt` | список `Task` |
| Приключения недели (5 шт.) | `data/content/AdventureContent.kt` | список `Adventure` |
| Товары магазина (11 шт.) | `data/content/ShopContent.kt` | список `ShopItem` |
| Цели копилки (4 шт.) | `data/content/GoalContent.kt` | список `SavingsGoal` |
| Фразы обратной связи (70 ключей) | `app/src/main/assets/content/feedback.json` | JSON «ключ → шаблон» |
| 3D-модели и раскраски кота | `app/src/main/assets/cat/` | GLB и WebP |

Задания, приключения, товары и цели сейчас описаны Kotlin-списками, а не JSON-файлами: для прототипа
это проще проверить компилятором и тестами. Всё равно это данные, а не логика: списки не содержат
условий и вычислений, их читают правила из `domain/` (`GameEngine`, `Task.evaluate`, `AdventureRules`)
и экраны из `presentation/`. Перенос в JSON — см. «Дальнейшее развитие» ниже.

### Как загружается

- `defaultContent()` (`data/content/DefaultContent.kt`) собирает все списки в один объект
  `Content` (`domain/content/Content.kt`). Koin отдаёт его как синглтон (`app/di/AppModule.kt`),
  ViewModel и репозиторий получают его через конструктор.
- `feedback.json` читается один раз при старте (`app/di/AssetsModule.kt`) функцией `parseFeedback`
  (`data/content/FeedbackContent.kt`) в объект `Feedback`. Лишний или пропущенный ключ — ошибка контента,
  а не пустая строка на экране.

### Что проверяют тесты

| Тест | Что гарантирует |
|---|---|
| `ContentMinimumsTest` | Минимумы **ТЗ 2.6**: ≥ 6 заданий, в каждой из трёх тем ≥ 2; у каждого задания с выбором ровно один верный вариант, и после любого варианта есть объяснение; ≥ 8 товаров двух типов; ≥ 3 целей; ≥ 9 раскрасок и ≥ 3 стадий |
| `AdventureContentTest` | Уникальные id и честные награды; в каждом вопросе есть верный ответ; варианты сюжета ссылаются на существующие выборы; сдача идёт после оплаты той же суммы; каждую оплату и корзину можно решить |
| `FeedbackContentTest` | В `feedback.json` есть непустой текст для каждого `FeedbackKey`, неизвестные ключи отклоняются, плейсхолдеры подставляются |
| `EconomyBalanceTest` | Цены товаров и целей работают вместе с экономикой: за 5 недель сбалансированный план растит Финни быстрее крайних стратегий и доходит до первой цели, доход за задания и приключения меньше 30% карманных ([11](11-economy.md)) |

Тексты интерфейса (кнопки, заголовки экранов, знакомство с игрой, словарик) лежат в Compose-экранах
рядом с разметкой: это часть интерфейса, а не учебный контент.

## Питомец

Питомец в игре один — кот: у него весь функционал (анимации эмоций, гардероб, поглаживание, голос).
Ребёнок выбирает раскраску и имя.

- Модели по стадиям роста: `assets/cat/{baby,teen,adult}.glb` — один скелет и набор анимаций.
- Раскраски: `PetColor` (`domain/pet/model/PetLook.kt`) — обычная рыжая (текстура из модели) и 8
  перекрашенных текстур шерсти в `assets/cat/skins/<цвет>.webp`. Итого 9 различимых вариантов (**ТЗ 2.6**).
- Вещи гардероба — узлы модели (`Acc_Cap`, `Acc_Glasses`, `Acc_BowTie`), одинаковые на всех стадиях.
  Какой товар какой узел включает — `presentation/pet/PetAssets.kt`.

## Задания — `TaskContent.kt`

Общая часть у всех типов:

```kotlin
data class Task(
    val id: String,
    val topic: TaskTopic,              // BUDGET | SAVINGS | PAYMENTS
    val title: String,
    val intro: String,                 // ситуация
    val reward: Int,                   // монеты за верное решение
    val rewardOnMistake: Int,          // монеты за попытку с ошибкой
    val explanationSuccess: String,    // объяснение после верного решения
    val explanationMistake: String,    // объяснение после ошибки и как исправить
    val hint: String,
    val payload: TaskPayload,          // механика, см. ниже
)
```

Рекомендации к текстам: `intro` ≤ 30 слов, объяснения ≤ 25 слов, числа ≤ 200, только + и −.

Механики (`domain/task/model/TaskPayload.kt`), оценка ответа — `Task.evaluate` (`domain/task/TaskEvaluation.kt`):

| Механика | Что делает ребёнок | Верно, если |
|---|---|---|
| `Choice` — ситуация с вариантами | Выбирает действие; у каждого варианта своё последствие (`consequence`) | выбран вариант с `correct = true` |
| `Allocate` — раздели сумму | Раскладывает `total` монет шагом `step` по кучкам «Нужное», «Желаемое», «Копилка» | сумма равна `total`, нужное ≥ `mandatoryMin`, копилка ≥ `savingsMin` |
| `ShopList` — собери покупки | Выбирает товары в пределах `budget`, экран показывает сумму и остаток | все обязательные выбраны и сумма ≤ `budget` |

### Текущие задания

| id | Тема | Механика | Суть | Награда / за ошибку |
|---|---|---|---|---|
| budget_split_60 | BUDGET | Allocate | Раздели 60 монет: еда 20, уход 10, отложи хоть немного | 5 / 3 |
| budget_first_what | BUDGET | Choice | 30 монет: шляпа за 30 или еда за 15 | 5 / 3 |
| savings_weeks | SAVINGS | Choice | Самокат за 60, откладываешь по 20 — через сколько недель? | 5 / 3 |
| savings_take_or_not | SAVINGS | Choice | В копилке 40 на велосипед за 120 — взять на чипсы или подождать | 5 / 3 |
| payments_shop_50 | PAYMENTS | ShopList | Собери покупки на неделю на 50 монет, нужное обязательно | 5 / 3 |
| payments_two_prices | PAYMENTS | Choice | Корм 15 и наклейки 5 отдельно или такой же корм за 25 с наклейками «в подарок» | 5 / 3 |

Каждое задание проходится и в правильном, и в ошибочном варианте, после любого есть объяснение
(**ТЗ 2.5.8, 2.6**; проверяет `ContentMinimumsTest`).

### Как добавить новое задание

1. Добавить объект `Task` в список `defaultTasks` (`TaskContent.kt`) с уникальным `id`, одной из трёх тем
   и одной из трёх механик.
2. Запустить `./gradlew :app:testDebugUnitTest` — `ContentMinimumsTest` проверит уникальность id, верный
   вариант и объяснения.
3. Всё. Правила, экраны и сохранение не трогаются: список заданий, награды и оценка берутся из контента.
   Если нужна новая **механика** — это уже новая функция: новый класс в `TaskPayload`, ветка в
   `Task.evaluate` и виджет на экране задания.

## Приключения недели — `AdventureContent.kt`

Мини-сценарий из нескольких шагов: одно приключение на неделю, по порядку списка. Числа внутри сцен свои
и реальный баланс не трогают — в игру уходит только награда (`reward` без ошибок, иначе `rewardOnMistake`).

Шаги (`domain/adventure/model/Adventure.kt`), проверка — `domain/adventure/AdventureRules.kt`:

| Шаг | Что делает ребёнок |
|---|---|
| `Story` | Читает кусочек сюжета; текст может зависеть от выбора в предыдущем `Choice` (`variants`) |
| `Pay` | Платит нужную сумму купюрами и монетами из кошелька |
| `Change` | Считает сдачу |
| `Choice` | Выбирает вариант, после любого — объяснение |
| `Basket` | Собирает корзину в пределах бюджета, обязательные позиции — обязательно |

| id | Название | Что тренирует |
|---|---|---|
| first_shop | Первый поход в магазин | оплата и сдача |
| park_walk | Прогулка в парке | выбор при небольшом бюджете, корзина |
| scratched_paw | Лапка | непредвиденный расход и зачем нужен запас |
| fair | Ярмарка | сравнение цен, оплата, сдача |
| friend_gift | Подарок другу | накопление на большую покупку |

Новое приключение добавляется так же, как задание: объект `Adventure` в `defaultAdventures`, затем
`AdventureContentTest`. Новый вид шага — новый класс в `AdventureScene` и виджет на экране приключения.

## Тексты обратной связи — `assets/content/feedback.json`

Плоский JSON «ключ → шаблон» с плейсхолдерами вида `{n}`, `{item}`, `{goal}`, `{price}`, `{plan}`, `{spent}`.
Ключи фиксированы в `FeedbackKey` (`domain/content/FeedbackKey.kt`): домен называет, что произошло,
а слова берутся из файла.

| Группа ключей | О чём |
|---|---|
| `ledger.*` | Причины движений в журнале монет: доход недели, задание, копилка, цель |
| `period.*`, `stage.up` | Итоги недели: что вышло с каждым делом, рост питомца |
| `deed.*` | Дела недели: что сделать |
| `finish.*` | Почему неделю пока нельзя закончить |
| `plan.*` | Подсказки в окне плана недели |
| `deposit.*`, `withdraw.*` | Копилка: отказ, снятие |
| `adventure.*` | Подсказки и объяснения в приключениях |
| `say.*` | Реплики Финни |
| `storage.*` | Ошибки сохранения, понятные ребёнку |
| `topic.*` | Названия тем заданий |

Пример:

```json
{
  "ledger.week_income": "Карманные деньги",
  "period.c_ok": "Ты отложил {n} — до мечты ближе",
  "finish.no_adventure": "На этой неделе тебя ждёт приключение. Оно в разделе «Задания»"
}
```

Правила текстов: без «ты виноват», «плохо», «неправильно». Ошибка описывается через питомца и
следующий шаг, не через оценку ребёнка (**ТЗ 3.5, 8.1**).

## Дальнейшее развитие

Перенести задания, приключения, товары и цели в JSON-файлы `assets/content/` рядом с `feedback.json`,
чтобы контент можно было менять без пересборки кода:

1. Описать DTO с `@Serializable` по образцу `data/settings/SettingsSaveFile.kt` и мапперы в доменные модели.
2. Читать файлы в `AssetsModule` так же, как `feedback.json`, и собирать из них `Content` вместо `defaultContent()`.
3. Оставить тесты контента: они будут читать JSON из `src/main/assets`, как `FeedbackContentTest`.

Доменные модели, правила и экраны при этом не меняются: они уже получают `Content` через конструктор.
